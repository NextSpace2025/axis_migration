# 2026-11-17 작업 기록

## 문서 내용에 따른 모델 설계와 변환

폴더명보다 파일 내부의 제목·헤더·본문을 기준으로 문서를 분류하고 표를 재구성하도록 스킬을 보강했다. 먼저 실제 문서에서 모델과 필드의 근거를 찾고, 요청한 전체 범위를 표현할 수 있는지 검토한 다음 변환한다. 대표 샘플 확인이나 원문 저장만으로 전체 변환이 완료됐다고 판단하지 않는다.

- 엑셀의 실제 셀·수식·저장 캐시를 우선 읽고 PDF 텍스트와 이미지/OCR을 구분한다.
- 상세·소계·누계·세액·합계와 실제 반복 행·사본을 구분한다.
- 확인되지 않은 수량·단위·가격 기준·통화·수정 관계는 추정하지 않는다.
- 읽기 정확성, 의미 매핑, 원문 상충, 산술, DB 무결성의 확인 결과를 구분한다.
- 회사명 → 공종 → 업무 → 세부작업의 분류 제안과 확정 회사 기준을 구분한다.
- 입력 폴더의 `.axis_migration/record.md`에 시작·진행·결정·결과 위치를 누적하고 다음 작업에서 먼저 읽는다.

기존 원본과 이전 실행 결과는 보존한다. 회사별 기록·설정·생성 데이터는 공개 패키지 밖에 두고, 새 로컬 변환 결과는 입력 폴더의 부모 아래 별도 실행 디렉터리에 저장한다.

## 문서 대조와 계산 검사

`construction-document-matching`을 추가해 요청이 있을 때 발주·명세 자료의 공급망 역할, 연결 근거, 수량·금액 차이와 미청구 항목을 검토하도록 했다. 같은 거래처·금액 또는 파일 배치만으로 문서를 연결하지 않으며 지급 승인으로 해석하지 않는다.

`scripts/reconcile.py`는 표준 라이브러리의 Decimal로 행 금액·공급가액·세액·합계·한글 금액 표기·누계·연결 물량을 대조한다. 관찰된 패턴이 있을 때 절사 가능성을 보고하고, 원문 값을 자동 수정하거나 차이를 맞추기 위한 조정 행을 만들지 않는다. 테스트에는 가상 자료만 사용한다.

## 실제 자료에 적용한 정리 작업

내용 기반 추출·구조화 후 금융 증빙의 OCR 결과를 원본과 대조하고 관련 엑셀·다른 증빙으로 보완했다. 원문 값과 별도 근거에서 확인한 보완값을 분리하고, 사용자 확인이 필요한 항목은 고정 질문 번호로 묶어 보류 상태를 유지했다.

확인된 데이터는 별도 최종 결과로 정리하고, 문서 종류별 시트와 답변 입력 시트를 갖춘 엑셀 합본도 생성·검증했다. 답변 입력과 검토 완료는 구분하며, 나중에 답변을 받으면 근거를 확인한 뒤 새 실행본에 반영하도록 재개 정보를 남겼다. 원문 미기재 값이나 기존 미변환 범위를 완료 처리하지 않았다.

이 항목은 이번 자료 적용에서 수행한 작업의 요약이다. 범용 OCR·엑셀 생성·증분 반영 엔진을 공개 패키지에 구현했다는 뜻은 아니다. 현장별 건수·보류 내용·원문 경로·상호·금액·산출물 링크·검증 이미지는 입력 폴더의 비공개 기록과 별도 결과 디렉터리에만 보관한다.

## 읽기 전용 대시보드와 테이블 설명

`scripts/view_db.py`에 외부 JSON 설명 사전을 연결하는 `--catalog` 옵션을 추가했다. 회사별 설명 사전은 공개 저장소에 넣지 않는다.

- 대시보드에서 분류별 한글 테이블명, 실제 행 수, 설명 검색을 제공한다.
- 각 테이블의 생성 이유, 한 행의 의미, 가능한 해석, 주의사항, 근거와 관련 표를 설명한다.
- 개별 테이블 화면에서도 실제 데이터 위에 설명을 표시한다.
- 서로 다른 테이블의 행 수를 거래 건수로 합치거나, 보충 상세·초기 보존본을 새 거래로 합산하지 않도록 안내한다.
- 검색 결과 없음, 빈 테이블, 좁은 화면과 가로 스크롤을 처리한다.

실행 예시:

```sh
python scripts/view_db.py /absolute/path/to/data.sqlite --catalog /absolute/path/to/table_catalog.json --page-size 50
```

설명 사전의 `tables` 항목은 실제 테이블명을 키로 사용한다. 테이블별로 `title`, `group`, `why`, `row_meaning`, `interpretation`, `caution`, `evidence`, `related`를 기록한다. 행 수는 연결한 DB에서 읽는다. 기존 설명 사전 없이 실행하는 조회 방식도 유지한다.

## 한글 컬럼명과 뜻·단위 안내

테이블별 `columns` 사전으로 한글 컬럼명과 뜻·단위·주의사항·단위 근거를 표시한다. 같은 원래 컬럼명도 테이블에 따라 다른 의미와 단위를 가질 수 있다.

| 설정 | 용도 |
|---|---|
| `label` | 화면의 한글 컬럼명 |
| `description` | 해당 테이블에서 컬럼이 뜻하는 값 |
| `unit` | 명시 단위 또는 원문·행별·미확정 단위 안내 |
| `unit_status` | 모델 명시·행 원문·문맥·미확정·비물리량 구분 |
| `notes` | 해석·합산·원문 확인 시 주의사항 |
| `unit_basis` | 단위 판단 또는 미확정 상태의 근거 |

머리글의 `뜻·단위` 링크는 해당 컬럼의 설명을 펼쳐 이동하고, `데이터 표로 돌아가기`로 조회를 이어간다. 표 위의 `컬럼 뜻과 단위 보기`에서는 컬럼 순서대로 전체 설명을 읽을 수 있다.

단위 전용 모델 필드의 mm·kg·kg/m·kg/SET·m²와, 행마다 달라지는 수량 단위를 구분한다. 수량 단위와 단가의 가격 기준이 같다고 가정하지 않는다. 원문에 없는 통화·측정 단위·비율 척도는 추정하거나 일괄 변환하지 않는다. 문자·식별자·상태에는 물리량 단위를 붙이지 않는다.

화면의 이름만 한글로 표시한다. 원래 DB 컬럼명은 함께 보여 주고, DB 값·스키마와 CSV·SQL 다운로드의 기존 컬럼명은 보존한다. 조회기는 계속 읽기 전용이며 `127.0.0.1`에만 바인딩한다.

## 검증과 남은 범위

전체 자동 검사는 다음 명령으로 실행한다.

```sh
python -m unittest discover -s tests -v
```

검사는 가상 자료를 사용한 변환 무결성, 정확 소수 대조, 조회·다운로드·페이지 이동, 대시보드 검색, 설명 이스케이프, 한글 컬럼과 단위, 기존 CSV 컬럼명 보존, 공개 패키지 경계를 포함한다. 실제 자료 적용에서는 원문 대조·DB 해시·메타데이터 연결과 넓은 화면·작은 화면의 설명 이동을 별도로 확인했으며 세부 결과는 비공개 기록에 남겼다.

Windows의 기본 CP949 인코딩에서 한글 SQL 예제를 읽지 못하던 검사도 수정했다. 가상 SQL·텍스트 예제는 UTF-8을 명시해 읽는다. 최종 전체 자동 검사 31개가 통과했다.

이번 변경은 원문·제작 도면·압축자료 전체의 자동 변환, 은행 지급 실행, 운영 DB 반영, 사용자 답변의 자동 확정을 제공하지 않는다. 릴리스 태그 발행이나 설치본 업데이트도 수행하지 않는다.
